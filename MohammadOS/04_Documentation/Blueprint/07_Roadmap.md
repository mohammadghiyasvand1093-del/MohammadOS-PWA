# Purpose

The Roadmap translates the long-term Mission into an executable sequence of milestones.

It answers one question:

> **What should be built next to reach the Mission?**

Unlike the Dashboard, which manages daily execution, the Roadmap manages long-term progression.

---

# Planning Hierarchy

MohammadOS follows a hierarchical planning model.

```
Mission
    ↓
Vision
    ↓
Career Phase
    ↓
Annual Goals
    ↓
Quarterly Goals
    ↓
Monthly Objectives
    ↓
Weekly Priorities
    ↓
Daily Execution
```

Each layer derives from the layer above it.

---

# Roadmap Principles

The Roadmap follows these principles:

* One active strategic direction.
* One active learning Gate.
* No parallel career paths.
* No random course collection.
* Every milestone must support the Mission.

If something cannot be connected back to the Mission, it does not belong in the Roadmap.

# Gate System

The Roadmap operates using Gates.

Each Gate contains:

* Objective
* Required Skills
* Completion Criteria
* Deliverables
* Estimated Duration

A new Gate begins only after the current Gate is completed.

---

# Milestones

Every milestone must satisfy four conditions:

* Measurable
* Time-bound
* Mission-aligned
* Produces a tangible output

Examples:

* Complete Linux Fundamentals
* Publish first GitHub project
* Finish Docker portfolio project
* Obtain first DevOps internship

---

# Constraints

The Roadmap respects system constraints.

Examples:

* University schedule
* Financial limitations
* Health
* Military service planning
* Available study time

Constraints affect scheduling but never change the Mission.

---

# Review Cycle

The Roadmap is reviewed:

* Weekly (progress check)
* Monthly (planning adjustment)
* Quarterly (major review)
* Annually (strategic review)

# Success Indicators

A healthy Roadmap always has:

* One current career phase
* One active Gate
* One next milestone
* Clear priorities
* No conflicting objectives
