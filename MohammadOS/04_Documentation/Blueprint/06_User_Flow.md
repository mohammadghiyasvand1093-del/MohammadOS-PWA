# User Flow

**MohammadOS — Personal Operating System**

**Module:** User Experience

**Version:** 1.0

**Status:** Stable

**Classification:** Blueprint

---

# Purpose

This document defines how Mohammad interacts with MohammadOS.

It specifies the standard workflow from the beginning of the day to the end of the day, ensuring consistency, focus, and alignment with the Constitution and Roadmap.

The goal is to reduce decision fatigue by establishing a repeatable operating cycle.

---

# Daily Operating Cycle

Every day follows the same high-level process.

```
Morning Review

↓

Daily Planning

↓

Deep Work

↓

Operational Tasks

↓

Learning

↓

Daily Review

↓

Prepare Tomorrow
```

---

# Step 1 — Morning Review

Before beginning work:

* Open Dashboard
* Read Today's Mission
* Check Active Gate
* Review Weekly Objectives
* Review unfinished tasks from yesterday

Objective:

Start the day with clarity.

---

# Step 2 — Daily Planning

Plan only today's work.

Questions:

* What is today's highest-value task?
* What supports the Active Gate?
* What can realistically be completed today?

Planning should take less than 15 minutes.

---

# Step 3 — Deep Work

Execute the most important work first.

Examples:

* Programming
* DevOps practice
* Building projects
* University assignments
* Writing documentation

Rules:

* No distractions
* No multitasking
* Complete the priority before moving on

---

# Step 4 — Operational Tasks

After Deep Work:

Complete operational responsibilities.

Examples:

* Email
* Messages
* Small maintenance tasks
* Administrative work

Operational tasks must not replace Deep Work.

---

# Step 5 — Learning

Study according to the Active Gate.

Learning should produce output.

Examples:

* Code
* Notes
* Projects
* Git commits
* Documentation

Watching videos alone is not considered completed learning.

---

# Step 6 — Daily Review

At the end of the day:

Review:

* Completed work
* Missed tasks
* Problems encountered
* Lessons learned

Update Dashboard if necessary.

---

# Step 7 — Prepare Tomorrow

Before closing the system:

* Select tomorrow's priority
* Capture unfinished ideas
* Clear temporary notes
* Close all active sessions

Tomorrow should begin with zero uncertainty.

---

# Weekly Cycle

Once each week:

* Review Weekly Dashboard
* Measure progress toward Roadmap
* Review Active Gate
* Archive completed tasks
* Plan next week's priorities

---

# Monthly Cycle

Once each month:

Review:

* Career progress
* Financial status
* Learning progress
* Health
* English
* Projects

Compare actual progress with Roadmap.

Adjust only tactics—not the Mission.

---

# Quarterly Cycle

Every quarter:

Conduct a strategic review.

Questions:

* Is the current roadmap still valid?
* Has the current Gate been completed?
* Are priorities still aligned with the Mission?
* What should be improved next quarter?

---

# Annual Cycle

Once each year:

Review the entire system.

Evaluate:

* Mission alignment
* Career phase
* Financial growth
* Skills acquired
* Major achievements
* Long-term direction

Annual reviews may update the Roadmap, but never contradict the Constitution without explicit revision.

---

# Operating Rules

The user should:

* Trust the system.
* Execute before optimizing.
* Review before changing.
* Archive before deleting.

Avoid making structural changes during periods of stress or emotional pressure.

---

# System Philosophy

MohammadOS exists to reduce cognitive load.

The system should answer:

* What should I do now?
* Why am I doing it?
* Where does this information belong?
* What is the next step?

If the user must frequently stop to think about how to use the system, the system needs improvement—not the user.
